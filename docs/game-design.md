# 遊戲企劃書：園遊會卡片收藏家

> 版本：0.3（學習紀錄串接版）  
> 狀態：素材、可玩 MVP 與匿名遊戲紀錄送出流程已完成；2026-10-25 已完成一局瀏覽器送出驗證，試算表收到六筆週決策與一筆結局摘要。平衡度與學習成效仍待目標玩家試玩。

## 1. 遊戲概念

一款給國小高年級學生玩的 2D 瀏覽器單人理財遊戲。玩家要在園遊會前的六週裡，靠每週零用錢和任務收入，規劃存款、因應事先揭露的事件，並克制或安排點心飲料消費，最後存到足夠的錢收齊一套動物／角色卡片。

工作名稱：**園遊會卡片收藏家：六週儲蓄挑戰**

| 項目 | 設計 |
| --- | --- |
| 玩家 | 國小高年級；企劃先以約 10–12 歲、會做整數加減與簡單除法為假設 |
| 平台 | 瀏覽器單人遊戲，繁體中文 |
| 類型 | 回合制資源規劃與生活理財遊戲 |
| 題材 | 園遊會、動物／角色卡片收藏、點心與飲料 |
| 金額 | 新台幣整數，不使用小數或利息計算 |
| 時間 | 六個回合，每回合代表一週；單局時間目標約 8–12 分鐘，待試玩確認 |

遊戲從現有 Phaser 遊戲入口直接開始；方向上不新增網站首頁或外部路由。必要的規則說明可以放在遊戲內的第一個畫面或提示層。

## 2. 學習目標與遊戲式學習設計

### 可觀察的學習成果

玩家能在固定總價與六週期限下，計算目標差額並安排每週儲蓄；當收入、任務條件或支出事件改變時，能重新調整任務選擇、存款與消費，並說明調整的理由。

### 學習目標到遊戲行動的對應

| 學習目標 | 玩家行動 | 規則與結果 | 可觀察的學習證據 |
| --- | --- | --- | --- |
| 算出固定收藏套組的總價與目標差額 | 查看卡片價格，建立六週儲蓄計畫 | 套組價格、目前基金、剩餘週數和差額持續顯示 | 玩家能說出目標金額，並提出可行的每週存款安排 |
| 在收入限制下安排儲蓄與想要的消費 | 每週選任務，再分配存款和點心／飲料開支 | 存款進入卡片基金；未使用的錢留在錢包並結轉；錢包不足時不能超支 | 玩家會比較任務報酬、消費和目標之間的取捨 |
| 收入或條件改變後修正計畫 | 在分配前閱讀當週事件，調整任務和剩餘週次的存款目標 | 事件先揭露；任務報酬與限制清楚可見；確認後依規則更新基金與錢包 | 玩家在事件後更新計畫，並能解釋哪個條件改變了選擇 |
| 從結果整理策略 | 園遊會結算時查看每週紀錄，回顧並重玩 | 未達標時呈現差額、事件和每週分配，不以單純「失敗」結束 | 玩家指出哪次選擇有效、哪次選擇造成差距，以及下次如何修改 |

### 學習回饋

- 回饋要說明結果和原因，例如：「本週任務少拿 NT$10，距離套組還差 NT$70；剩下兩週，平均每週要存 NT$35。」
- 事件公布後，更新「剩餘目標 ÷ 剩餘週數」的參考值；初期提供明確提示，後續可逐步減少提示。
- 任務條件、報酬、事件影響和可用金額都在決策前顯示，讓玩家能理解選擇與後果的關係。
- 點心或飲料是合理的個人選擇，不標示為錯誤行為；遊戲呈現的是它對期限和收藏目標的影響。
- 分數和卡片動畫用來回饋進度，不單獨作為學會理財的證據。另以玩家的計畫、調整和結尾說明觀察理解程度。

## 3. 核心規則與遊戲循環

### 遊戲目標

六週結束時，卡片基金達到固定套組總價 NT$290，玩家即可在園遊會收齊整套卡片。卡片名稱、圖片和各自價格在遊戲開始時就可查看，避免目標在遊戲中途改變。

### 開始遊戲

1. 說明園遊會日期、卡片套組和總目標金額。
2. 顯示起始錢包、卡片基金和六週期限。
3. 玩家先建立一份簡單的初始存款計畫；可以先以平均分配作為支援，再允許玩家自行修改。

### 每週回合

1. **開始新的一週**：顯示固定零用錢、目前錢包、卡片基金、目標差額和剩餘週數。
2. **揭露事件**：事件在玩家分配前出現，清楚說明會改變的收入、任務條件或支出。
3. **選擇任務**：從數個任務卡中選擇；每張卡顯示報酬、限制和當週是否可做。任務結果固定，不用額外小遊戲或隨機擲骰決定報酬。
4. **分配金額**：玩家決定存入卡片基金的金額，以及是否購買點心或飲料。沒有花掉的錢留在錢包，帶到下一週。
5. **結算並調整**：顯示零用錢、任務、事件和消費如何影響結果；更新基金、錢包和剩餘週次的參考存款額，讓玩家調整後續計畫。

### 結局與重玩

- 六週後達到總目標：在園遊會收齊卡片套組，呈現每週計畫與實際存款的摘要。
- 六週後尚未達標：顯示已存金額、差額、每週紀錄，以及哪些決策改變了結果；提供調整策略後重玩的按鈕。
- 事件順序在 MVP 中採固定編排，讓玩家能比較不同策略的結果，避免純運氣掩蓋學習內容。

### 計算規則

```text
本週可用金額 = 上週錢包結餘 + 本週零用錢 + 任務收入 + 事件調整
本週結餘     = 本週可用金額 - 存入卡片基金 - 點心／飲料支出
```

事件可影響特定任務報酬、必要支出或飲料價格；事件內容、任務條件與變更後金額都會在玩家分配前揭露。初期只用整數新台幣。每週參考存款額以 NT$5 為步進，向上取整以涵蓋剩餘目標。

## 4. MVP 範圍

### 要驗證的設計問題

國小高年級玩家能否在六週、固定卡片目標、可變任務收入與預先揭露事件下，安排存款和消費，並在情況改變時修正計畫？玩家是否能說明自己的策略，而不只是碰巧達標？

### MVP 必須包含

- 一套固定卡片收藏目標，總價與各卡片價格清楚可見。
- 六週回合、固定每週零用錢，以及每週兩項報酬和成本不同的任務選項。
- 每回合一張在分配前揭露的事件卡；事件順序先固定。
- 錢包、卡片基金、點心／飲料消費與未用餘額結轉。
- 初始儲蓄計畫、每週計畫調整、目標差額和剩餘週次參考額。
- 六週結算、可解釋的未達標回顧和調整策略重玩。
- 一套已挑選並檢查過的 Kenney 素材；卡片、任務、事件、點心與基本介面有一致的視覺語言。

### MVP 暫不包含

- 多人、排行榜、帳號、雲端存檔或教師管理後台。
- 需要反應速度或知識測驗才能拿到任務收入的小遊戲。
- 隨機事件、複雜利息、信用卡、百分比或小數計算。
- 多套收藏、自由編輯關卡或大型故事分支。

### MVP 經濟設定（尚待試玩平衡）

目前實作採用每週固定零用錢 NT$30，六張卡片價格為 NT$35、40、45、50、55、65（總價 NT$290），每週兩項任務（報酬 NT$15–35，部分任務需先付材料費），以及固定排序的六張事件卡。可選消費為飲料（一般 NT$10，第五週特價 NT$5）和點心（NT$20）；第四週另有 NT$10 必要支出。初始參考存款為每週 NT$50，可在開始畫面以 NT$5 為單位調整；之後依目標差額與剩餘週數更新參考額。

成功路徑與未達標路徑已各自人工遊玩至結局：高報酬任務配合調整存款可收齊卡片；低報酬任務搭配每週買點心時，結算會顯示基金差額和逐週回顧。這些結果只確認遊戲規則和畫面流程可運作，尚未由目標年齡玩家驗證難度或教學效果。後續試玩應檢視：

- 至少有一條符合規則、可在六週內達標的策略。
- 若每週都採取某種常見消費／低報酬任務，能看出為何會有差額，而非突然失敗。
- 玩家不必猜測事件或任務成功率；作出選擇前看得到足夠資訊。
- 金額不會因錯誤操作變成負數，且每個狀態轉移都能用上述公式解釋。

## 5. 素材選擇

已選定 [Kenney Animal Pack Remastered](https://kenney.nl/assets/animal-pack-remastered) 作為卡片插圖素材。它是 2D 素材套件，官方套件授權檔標示 CC0。實際使用 `PNG/Round` 的長頸鹿、企鵝、青蛙、樹懶、大象、貓頭鷹六張插圖；卡片框、面板、事件卡和按鈕以 Phaser Graphics 繪製，沿用同一組色彩，不混入第二套畫風。只有六張遊戲實際使用的 PNG 放在 `public/assets/`，完整原始套件和授權檔留存於 `asset-source/`。

完整選擇與來源記錄見 [`asset-source/kenney/animal-pack-remastered/selection.md`](../asset-source/kenney/animal-pack-remastered/selection.md)，套件檔案清單與聯絡表也保存在同資料夾。點心、飲料和事件目前以文字和色塊呈現；下一輪若需要圖示，再先確認同風格素材是否合適。

## 6. 實作步驟與迭代順序

實作依序完成：**素材挑選 → 可玩 MVP → 分階段迭代。**前兩步已完成，接下來進入目標玩家試玩和迭代。

### 步驟 1：完成素材挑選（已完成）

1. 已查看 Kenney 官方目錄和 Animal Pack Remastered 預覽。
2. 已檢視實際圖片、尺寸、格式與檔案清單，選定六張卡片插圖及 Phaser Graphics 介面作法。
3. 已確認套件授權、保留來源清單，只把遊戲使用的六個 PNG 放進 `public/assets/`。
4. 已記錄卡片圖檔對照；任務、事件、點心／飲料和介面以文字或同色系圖形呈現。

### 步驟 2：完成可玩 MVP（已完成）

1. 已用 Phaser 實作單人六週核心流程。
2. 已把經濟數值與任務／事件資料集中管理，方便平衡調整。
3. 已實作起始計畫、任務挑選、事件揭露、基金／錢包分配、結算和重玩。
4. 已接入挑選好的動物插圖，並以滑鼠操作畫面檢視主要金額和選項。
5. 已人工走過達標和未達標流程；玩家理解與策略說明仍待目標年齡試玩確認。

### 迭代一：核心平衡與可理解性

- 觀察幾位目標年齡玩家實際選擇，記錄停頓、誤讀、存款計畫及事件後調整。
- 試問玩家為何選該任務、存這個金額、買或不買點心；不要只看是否完成或停留時間。
- 調整零用錢、任務報酬、事件支出、卡片價格、提示措辭和每週參考存款額。
- 確保成功來自看得懂並使用資訊，而非碰運氣；確保失敗能指出有用的下一步。

### 迭代二：分段教學與支援

- 第一週提供目標差額和平均存款示例，先讓玩家熟悉計算。
- 後續週次逐步減少提示，加入需要比較兩種任務或修正計畫的情境。
- 為容易困惑的詞（例如「基金」「結餘」）加簡短文字或圖示解釋。
- 讓玩家能回看過去週次的收入、支出、存款和事件。

### 迭代三：內容和難度擴充

- 在核心循環驗證後，新增第二套卡片或另一組六週事件／任務情境。
- 以不同收入與目標金額安排簡單／標準挑戰，不以增加隨機性作為難度來源。
- 引入生活情境轉移題，例如「下個月想存錢買書，遇到臨時支出時怎麼改計畫？」

### 迭代四：介面、無障礙和完成度

- 檢查桌面與平板瀏覽器版面、點擊區、文字大小、色彩對比及鍵盤可操作性。
- 加入簡短動效、音效與結尾收藏展示，但不讓裝飾蓋過數字和決策資訊。
- 在結果畫面安排一個短回顧問題，讓玩家說明一次成功調整或下次會改變的選擇。

## 7. Phaser 專案落點

目前程式已落在以下結構，不新增網站首頁：

```text
src/game/
├── data/
│   └── economy.js          # 零用錢、六張卡價格、任務、事件和消費資料
├── systems/
│   └── BudgetRules.js      # 收入、錢包、基金、結算規則
├── scenes/
│   └── MainScene.js        # 開始畫面、六週流程、結局與重玩
└── ui/
    ├── draw.js             # Phaser Graphics 面板、按鈕、文字與進度條
    └── theme.js            # 遊戲色盤與新台幣格式

public/assets/images/kenney/
└── animal-pack-remastered/cards/  # 六張已挑選的動物卡插圖
```

先把規則計算與資料獨立出來，讓迭代能快速更換價格和事件。MVP 不需要帳號、遠端服務或複雜存檔。

## 8. 學習成效檢視

遊戲完成率、卡片數和重玩次數可用來理解遊玩過程，但不能單獨證明學會儲蓄規劃。試玩時至少記錄：

- 玩家是否在第一週建立明確可行的儲蓄計畫。
- 事件揭露後，有沒有調整任務或後續每週目標。
- 玩家能否口頭解釋一項任務／消費決策如何影響目標。
- 玩完後能否在一個不同數字的新情境中估算所需存款並說明調整方式。

將投入度、是否完成、當下理解和新情境轉用分開觀察；不把點數或操作紀錄當成理解本身。

## 9. 下一步：迭代前驗證

- 約 10–12 歲的年齡假設與實際玩家年級是否吻合。
- 套組卡片數量、逐張價格、零用錢、任務報酬與事件幅度。
- 玩家是否理解「錢包結餘」和「卡片基金」是兩種用途不同的錢。
- 每週數個任務的選擇是否有實際取捨，或玩家只會固定選報酬最高的一項。
- 玩家是否能從文字與畫面理解錢包、卡片基金、必要支出和存款參考額。

素材挑選與 MVP 已完成。先安排幾位國小高年級玩家進行一次不提示的完整遊玩，觀察他們如何制定起始計畫、理解事件、選擇任務，以及調整存款或消費；遊玩後請他們用自己的話解釋一次取捨。整理觀察後，再進入迭代一調整經濟數值與提示。不要只用是否通關判定學會理財。

## 10. 學習紀錄串接

- Phaser 每週結算時送出一筆 `weeklyDecision`，包含事件／任務 ID、任務報酬與成本、可分配金額、計畫與實際存款、消費、基金和錢包前後狀態；結局時送出一筆 `runSummary`。
- 記錄使用隨機遊玩 ID，不送出姓名或 Email。傳送失敗時先放在瀏覽器本機佇列，後續再嘗試；唯一 `event_id` 供 Apps Script 去重。
- `Reflections` 分頁目前只預留欄位，遊戲尚未提供轉移情境題或解釋題。遊戲紀錄呈現的是玩家行為與結果，仍需搭配試玩觀察或後續題目評估理解與轉用。
- Apps Script 目前設定為匿名可存取；端點網址會出現在瀏覽器端，任何取得網址的人都可能呼叫。現有驗證可檢查格式和金額關係，無法取代身分驗證或防濫用。試玩階段只傳送匿名、低敏感資料。
- Phaser 使用 `VITE_EVIDENCE_ENDPOINT` 設定端點；Vite 會將 `VITE_` 變數放入瀏覽器程式，因此端點網址不是密鑰。瀏覽器可能無法讀取 Apps Script 的跨來源回應；遇到此情況會嘗試單向送出，但不能從遊戲端確認試算表是否收到，須在試算表檢查。
